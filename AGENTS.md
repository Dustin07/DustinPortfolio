# Working on DustinPortfolio

- Read `CHANGELOG.md` and `README.md` before proposing or implementing changes. The change log records completed work and retired approaches; it is not a backlog.
- Inspect current source and behavior before claiming an existing feature is missing. Fix a concrete remaining issue instead of rebuilding a recorded improvement.
- Preserve the current user's constraints: free static GitHub Pages hosting, clean static background, full-width Experience & Education introduction, restrained optional motion, responsive layouts, reduced-motion support, unaccented Resume, and original documents.
- Keep engineering claims grounded in the existing public material or the user's supplied evidence. Preserve contribution, simulation, validation, and production-status distinctions.
- Follow the asset-versioning, related-work generation, document-integrity, and verification workflow in `README.md`. Do not publish temporary localhost fixtures or private workspace progress records.
- Add a dated `CHANGELOG.md` entry after every meaningful batch. Record the resulting behavior, affected files, checks, and any pending deployment gate. Retain earlier entries; mark replaced decisions as superseded.
- A committed change is not proof of a deployed change. Confirm GitHub Actions and the live site before reporting it live.
- Current user instructions take precedence over historical design decisions. When the user deliberately changes direction, record that decision so future work does not restore an outdated approach.
